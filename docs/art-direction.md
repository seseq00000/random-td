# 공중 제거 + 숲속 자경단 아트 — ✅ 구현 완료

> 게임 시스템 설계 원본은 `docs/design.md`. 이 문서는 아트 디렉션 계획이며 **전부 구현됐다.**
> 구현 중 계획과 달라진 부분은 각 절에 ⚠ 로 표시했다.

## 계획과 달라진 것

| 계획 | 실제 | 왜 |
|---|---|---|
| 저격 사거리 7 | **6** | 7 로 올렸더니 uptime 급등 — 기본 경제만으로 클리어율 32%. **사거리가 유효 출력의 지배 변수**다 |
| `WAVE_POOL_GROWTH` 만 조정 | **BASE 300→900 + GROWTH 1.39→1.34** | growth 만 올리면 후반이 절벽이 되어 전 전략 0%. 초중반을 올리고 후반을 낮추는 **모양 변경**이 필요했다 |
| 슬롯 가격 유지 | **총 1,450 → 4,520** | 공중이 사라지자 전 전략이 T7 도달 → 티어가 실력 차를 못 만들고 슬롯만 남았다. 슬롯을 진짜 병목으로 만들어 스프레드 복원 |
| 도전 보상 유지 | **보스 hpMul 1.5→1.3, 보상 ↑, 피버 골드 ×4.0** | 난이도가 올라 도전이 항상 손해가 됐다 (37% < 39%) |

## Context

싱글플레이는 완성됐지만(M1~M4 + 닉네임·기록) 화면이 **색상 도형 + 한글 한 글자**다.
`단/광/공/제/관/버` 를 네모에 찍고 적은 색깔 원이라, 기능은 읽히지만 게임처럼 보이지 않는다.

"귀여우면서 유니크한" 방향으로 **숲속 동물들이 몬스터를 막는** 테마를 입힌다.

아트를 논의하다가 **공중 적을 빼기로** 결정했다. 공중은 웨이브 7·12·16·21·23·24·27·28 에 나오고
**대공 또는 제어 유닛이 없으면 웨이브가 통째로 누출된다.** 랜덤 뽑기 게임에서 특정 역할이
안 나왔다는 이유로 판이 끝나는 건 가혹하다 (M3 문서에 경고로 적어둔 문제다).

이건 아트가 아니라 시스템 변경이므로 **먼저** 처리하고, 밸런스를 다시 맞춘 뒤 그림을 올린다.

### 확정된 방향

| 항목 | 결정 |
|---|---|
| 공중 적 | **제거** — 남는 적 3종(일반·장갑·물량) + 보스 |
| 대공 역할 7종 | **장거리 저격으로 전환** (역할 6개·42종 유지) |
| 빈 웨이브 8개 | 기존 3종으로 고르게 재분배 |
| 아트 테마 | 숲속 자경단 (동물 6종, 역할별 고정) |
| 유닛 이름 | 기존 SF 이름 + 티어마다 승급하는 동물 애칭 |
| 티어 표기 | T1·T2 는 숫자, **T3 부터 레어/유니크/에픽/레전드/신화** |
| 렌더링 | Canvas 벡터 (이미지 파일 0개) |

> ⚠ 적이 3종이면 **이중 스폰(W21+) 조합이 3가지뿐**이다. 후반이 반복적으로 느껴지면
> 그때 새 타입(예: 빠른 돌격형)을 추가하는 게 낫다. 지금은 추가하지 않는다.

# 1단계 — 공중 제거 (시스템)

## 1.1 타입 정리 — 죽은 코드를 남기지 않는다

| 파일 | 작업 |
|---|---|
| `src/core/types.ts` | `EnemyType` 에서 `'air'` 제거. `TargetType` 을 `'ground' \| 'none'` 으로 축소 |
| `src/core/combat.ts` | `canTarget` 이 `targetType !== 'none'` 으로 단순해진다 |
| `src/data/waves.ts` | `TYPE_MODIFIERS.air` 제거, `WAVE_SCHEDULE` 재분배 |

`'both'` 는 공중이 없으면 `'ground'` 와 같아지므로 남기지 않는다.
구조는 유지하므로 나중에 공중을 되살리고 싶으면 `TargetType` 에 다시 넣으면 된다.

## 1.2 대공 → 장거리 저격

`ROLE_SPECS` 의 `antiair` 를 `sniper` 로 **이름까지 바꾼다.** 키만 남기면 오해를 부른다.

- `targetType: 'air'` → `'ground'`
- `range: 6` → **7** (전 역할 중 최장)
- `dpsMul: 1.2` → **1.1**

사거리를 올리고 DPS 를 낮춰 `single`(range 4 / dpsMul 1.4) 과 역할이 겹치지 않게 한다.
**멀리서 약하게** vs **가까이서 세게**. 최종 수치는 2단계 시뮬레이터로 확인한다.

키 이름이 바뀌는 곳: `types.ts` 의 `Role`, `ROLE_SPECS`, `render/renderer.ts` 의 `ROLE_STYLE`,
`sim/strategy.ts` 의 도전 판단(`roles.filter`), 테스트.

**이름 7개 교체** (대공/우주 계열은 지상 저격과 안 맞는다):

| T1 | T2 | T3 | T4 | T5 | T6 | T7 |
|---|---|---|---|---|---|---|
| 망원포 | 원거리포 | 관측포 | 초장포 | 지평선포 | 대륙간포 | 무한사정포 |

## 1.3 웨이브 재분배

공중이 있던 8개 슬롯을 일반·장갑·물량으로 채운다. 원칙:

- **같은 타입이 연달아 오지 않게** 한다
- 장갑을 W7 로 앞당겨 방어력 개념을 조금 일찍 소개한다
- 보스(5의 배수)와 이중 스폰 시작(W21)은 그대로

예: `W7 air → armored`, `W12 air → swarm`, `W21 [normal, air] → [normal, swarm]`, `W23 [air, swarm] → [normal, armored]`

`waves.ts` 는 이미 로드 시점에 **보스 위치·이중 스폰 시작 웨이브·빈 타입**을 assert 하므로
재분배 실수는 바로 터진다.

## 1.4 테스트 정리

공중 전제로 쓰인 테스트를 지우거나 고친다:

- `combat.test.ts` — "공중 규칙" 5개 (`ground` 는 공중을 못 때린다 등)
- `data.test.ts` — "공중은 대공 유닛을 확보할 시간을 준 뒤에 나온다", `TYPE_MODIFIERS` 검증
- `challenge-wave.test.ts` — "공중 그룹은 웨이브 7부터만 등장한다"
- 역할 키 `antiair` → `sniper` 참조 전부

# 2단계 — 밸런스 재측정

공중 제거는 난이도를 **두 방향으로 내린다**:
1. "대공 없으면 전멸" 웨이브 8개가 사라진다
2. 대공 유닛 7종이 항상 유효해져 보드 전력이 오른다

```bash
npm run sim -- --runs=250
```

M4 에서 세운 목표를 다시 만족시킬 때까지 `data/` 수치만 조정한다:

| 전략 | 목표 |
|---|---|
| 기본 경제만 | 클리어 ≤2% · 평균 W17~20 |
| 미션 적극 | 평균 W24~27 |
| 미션+도전 | 클리어율 35~50% |
| 도전 남발 | full 보다 나빠야 |

1순위 조정 후보는 `WAVE_POOL_GROWTH`(현재 1.39). **아트 작업 전에 이 단계를 끝낸다** —
바뀔 시스템 위에 그림을 올리면 두 번 일하게 된다.

# 3단계 — 숲속 자경단 아트

## 3.1 현재 구조가 주는 제약

1. **타일 40px, 타워 30×30** — 디테일이 안 보인다. **실루엣과 색이 전부**다
2. **역할 6종이 기능적으로 뚜렷하다** — 테마가 기능과 맞으면 **외울 필요가 없다**
3. **42종이지만 캐릭터는 6개면 된다** — 티어는 색 등급으로 표현한다

## 3.2 동물 매핑

역할의 기능과 생김새가 1:1로 맞는 것만 골랐다.
**고슴도치가 가시를 직선으로 쏘는 걸 보면 관통이라는 걸 안다** — 설명이 필요 없다.

| 역할 | 동물 | 어근 | 몸통색 | 40px 에서 읽히는 단서 |
|---|---|---|---|---|
| single 단일 딜러 | 고양이 | 냥 | 주황 `#e08a4a` | 뾰족한 삼각 귀 2개 |
| splash 광역 | 곰 | 곰 | 갈색 `#8a6244` | 둥근 귀 2개, 큰 몸집 |
| **sniper 장거리** | 올빼미 | **빼미** | 청회색 `#6f8ba8` | 큰 눈 2개 + 부리 |
| control 제어 | 나무늘보 | 늘보 | 연갈색 `#a89878` | 처진 눈, 긴 팔 |
| pierce 관통 | 고슴도치 | 도치 | 짙은갈색 `#6a5240` | **등의 삼각 가시** |
| buff 버프 | 강아지 | 멍 | 크림 `#e8d5a8` | 늘어진 귀 2개, 꼬리 |

멀리 보는 올빼미가 최장 사거리를 맡으니 **대공에서 장거리로 바꾼 게 오히려 더 잘 맞는다.**

**다이소 미션(한 티어 6종 수집)이 "동물 6마리 모으기"가 된다** — 목표가 그림으로 읽힌다.

## 3.3 이름 — 갭 유머

기존 SF 이름을 두고 애칭을 뒤에 붙인다. `절대영도 늘보경`, `빅뱅포 곰왕`, `종결자 냥신` —
**무시무시한 이름과 귀여운 애칭의 갭**이 이 게임의 톤이 된다.

| 동물 | T1 | T2 | T3 | T4 | T5 | T6 | T7 |
|---|---|---|---|---|---|---|---|
| 고양이 | 아기냥 | 냥이 | 냥님 | 냥경 | 냥장 | 냥왕 | 냥신 |
| 곰 | 아기곰 | 곰이 | 곰님 | 곰경 | 곰장 | 곰왕 | 곰신 |
| 올빼미 | 아기빼미 | 빼미 | 빼미님 | 빼미경 | 빼미장 | 빼미왕 | 빼미신 |
| 나무늘보 | 아기늘보 | 늘보 | 늘보님 | 늘보경 | 늘보장 | 늘보왕 | 늘보신 |
| 고슴도치 | 아기도치 | 도치 | 도치님 | 도치경 | 도치장 | 도치왕 | 도치신 |
| 강아지 | 아기멍 | 멍이 | 멍님 | 멍경 | 멍장 | 멍왕 | 멍신 |

> 어근이 2글자인 빼미·늘보·도치는 T2 에서 `-이` 를 붙이지 않는다(`빼미이` 가 어색하다).
> 공식에 예외를 두는 대신 **7개씩 명시한 배열**로 둔다 — `data/` 는 손으로 튜닝하는 곳이다.

최종 이름 = `기존이름 + 공백 + 애칭`. 가장 긴 `종말의겨울 늘보신`(9자)도 벤치 카드에 들어간다.

## 3.4 티어 등급명

숫자 T3~T7 을 **등급명**으로 바꾼다. T1·T2 는 숫자 그대로 둔다 — 초반엔 등급을 붙일 만큼
특별하지 않고, 등급명이 T3 부터 시작해야 "레어를 뽑았다"는 순간이 살아난다.

| 티어 | T1 | T2 | T3 | T4 | T5 | T6 | T7 |
|---|---|---|---|---|---|---|---|
| **표기** | T1 | T2 | **레어** | **유니크** | **에픽** | **레전드** | **신화** |
| **색** | 회색 `#9aa4b0` | 초록 `#6fbf73` | 파랑 `#4aa8e0` | 보라 `#a06ae0` | 주황 `#e08a3c` | 빨강 `#e0574a` | 금색 `#f0c651` |

**표기 위치를 나눈다** — 40px 타일에 "레전드" 네 글자는 안 들어간다:

| 어디 | 무엇을 |
|---|---|
| 필드 타워 (40px) | **숫자 + 테두리 색** — 지금처럼 |
| 벤치 카드 · 미션 · 결과 화면 · 툴팁 | **등급명** (`레어 · DPS 324`) |
| 시뮬레이터 출력 | 숫자 — 평균 티어가 소수(`6.4`)라 등급명을 못 쓴다 |

`data/tiers.ts` **(신규)** 에 이름과 색을 **함께** 둔다. 둘 다 손으로 튜닝하는 값이고,
"티어 N 은 뭐라 부르고 무슨 색인가"를 한 곳에서 보는 게 낫다.

## 3.5 시각 규칙

**역할 = 실루엣 / 동물 = 몸통색 / 티어 = 테두리 등급.** 세 축이 겹치지 않아 동시에 읽힌다.
(지금은 역할이 색을 쓰고 티어가 숫자라 티어가 잘 안 읽힌다.)

- 각성(T7 3개 합성)은 금색 테두리 + **바깥 광채 링**. 등급명은 `신화 ★`
- 벤치 카드 `glyph` 를 `단/광/공/제/관/버` → **`냥/곰/빼/늘/도/멍`** 으로.
  한 글자로 동물이 읽혀서 DOM 카드마다 캔버스를 심지 않아도 된다

## 3.6 몬스터

적도 **미워할 만큼만 못생기게** 한다. 단 **기능 가독성이 최우선**이다.

| 타입 | 캐릭터 | 시각 단서 |
|---|---|---|
| normal | 슬라임 | 둥근 몸 + 점 눈 2개 |
| armored | 투구 슬라임 | 딱딱한 껍질 + 두꺼운 테두리 (지금 규칙 유지) |
| swarm | 미니 슬라임 | 작고 많다 |
| boss | 슬라임 왕 | 크고 왕관 |
| 도전 보스 | 그림자 왕 | 왕관 + 금색 테두리 (내가 부른 것) |

## 3.7 필드 톤

다크 UI 는 유지하되 숲으로 바꾼다.

- 배치 가능 타일: 이끼/풀 (`#232f26` / `#1e2921` 체크)
- 경로: 흙길 (`#4a3d2a`)
- 투사체를 역할별로: 도치=가시(삼각), 냥이=발톱, 곰=바위, 빼미=깃털, 늘보=눈송이

## 3.8 아트 작업 파일

| 파일 | 작업 |
|---|---|
| `src/data/tiers.ts` **(신규)** | 티어 등급명 + 등급 색, `tierLabel(tier)` |
| `src/data/creatures.ts` **(신규)** | 역할↔동물: 어근·몸통색·1글자 표기·애칭 7단계 배열 |
| `src/data/units.ts` | `buildUnit` 의 `name` 에 애칭 조합. **다른 필드는 안 건드린다** |
| `src/render/creatures.ts` **(신규)** | 동물 6종 + 몬스터 5종을 Canvas path 로 |
| `src/render/renderer.ts` | `ROLE_STYLE`/`ENEMY_STYLE` 교체, 배경 타일, 투사체, 티어 테두리 |
| `src/ui/style.css` | 숲 톤, 카드 테두리를 티어 등급 색으로 |
| `src/main.ts` | glyph 참조 + `T${tier}` 를 `tierLabel(tier)` 로 (카드·미션 툴팁·결과 화면) |

**아트 단계에서 밸런스 수치는 건드리지 않는다.** 2단계에서 맞춰놓은 균형이 흔들리면 안 된다.

# 4단계 — 정보 UI

## 4.1 지금 없는 것

| 있는 것 | 없는 것 |
|---|---|
| 벤치 카드의 `T4 · DPS 324` | **필드 타워를 클릭해도 스탯이 안 나온다** (사거리 원만) |
| 카드 호버 시 사거리 한 줄 | 역할이 실제로 뭘 하는지 수치 (스플래시 1.2타일, 슬로우 35%/1.5초, 관통 3명, 버프 +25%) |
| 미리보기 칩의 개체 HP·방어 | 공격력·공속이 DPS 로 뭉쳐 있어 따로 안 보인다 |

**아트 변경이 이걸 더 중요하게 만든다.** 지금은 `단/광/공/제/관/버` 글자라도 역할이 읽히는데,
동물 실루엣으로 바꾸면 "이 고슴도치가 뭘 하는 애인지" 알려줄 곳이 필요하다.

## 4.2 유닛 상세 슬롯 (패널 상단 고정)

벤치 카드에 **호버**하거나 필드 타워를 **선택**하면 패널 상단에 뜬다. 아무것도 안 고르면 숨긴다.

- 이름 · 등급명(등급 색) · 동물/역할
- **공격력 / 공속(회·초) / DPS** — 뭉치지 않고 따로
- 사거리(타일)
- 특수 효과 — 역할별로 있는 것만: 스플래시 반경, 슬로우 `65% 속도 · 1.5초`, 관통 `최대 3명`, 버프 `인접 +25%`
- 타겟 우선순위를 한글로: `선두 우선` / `근접 우선` / `강한 적 우선`
- 각성이면 **×2 반영된 실효 수치**로 표시
- 투입 골드와 판매 환급액 (`paid` 기반이라 개체마다 다르다)

## 4.3 도감 + 역할 범례 (오버레이)

**둘을 한 오버레이에 합친다** — 범례만 따로 두면 UI 가 하나 더 늘어난다.
입장/결과 화면에서 쓰는 `.overlay` 패턴을 그대로 재사용한다.

- **상단 범례**: 동물 6종 × 한 줄 설명. `🦔 도치 — 관통: 직선으로 최대 3명을 꿰뚫는다`
- **하단 도감**: 7행(티어) × 6열(역할) = 42칸 그리드
  - **지금 보유** — 밝게 + 개수 뱃지
  - **발견했었음** — 반투명 (localStorage 에 영구 누적)
  - **미발견** — 실루엣만 어둡게
- 티어 행이 전부 밝으면 **그 줄이 곧 다이소 미션 달성**이다 — 미션 진행이 그림으로 읽힌다

> 벤치 카드에는 캔버스를 안 심는다고 했는데(매 프레임 갱신이라 무겁다), **도감은 열 때 한 번만
> 그리므로** 42칸에 32px 캔버스를 써도 된다. 그래서 도감에는 글자가 아니라 진짜 동물이 들어간다.

발견 기록은 `RecordStore` 에 키 하나를 더한다(`random-td:discovered:v1`).
판이 끝날 때 그 판에서 보유했던 `defId` 를 합집합으로 누적한다.

## 4.4 적 정보 — 미리보기 칩 툴팁 강화

새 UI 없이 이미 있는 칩의 `title` 을 채운다. **판단이 필요한 시점(준비 페이즈)에 바로 보인다.**

- 도감에서 **티어 행이 다 밝아지는 것 = 다이소 달성**이 눈에 보이는가
